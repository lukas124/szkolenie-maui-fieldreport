# Ćwiczenie 04 — Z ręcznego składania na kontener DI

**Blok:** 04 · Wstrzykiwanie zależności (ang. Dependency Injection) · dzień 1 · **Start:** gałąź `04-di-start` · **Czas:** 7 min

## Cel
Dane zgłoszeń za interfejsem repozytorium, a obiekty aplikacji składa kontener DI zamiast ręcznego kodu w `App`
(„przed”: gałąź startowa, „po”: checkpoint `04-di`).

## Co jest w gałęzi startowej
- `Core/Data/IReportRepository` (GetAll, Get, Save, Delete) + `InMemoryReportRepository(IClock clock)` z danymi przykładowymi (`SampleReports`)
- `Core/Services/ReportService(IReportRepository repository) : IReportService` (sortowanie od najnowszej aktualizacji) + test z Moq
- `Core/Services/IClock` + `App/Services/SystemClock`
- `ServiceCollectionExtensions` z metodami `AddCoreServices`, `AddPlatformServices`, `AddViewModels`, `AddPages`
  (wołane w `MauiProgram`); `AddCoreServices` jest jeszcze pusta
- **Stan „przed”:** kontener trzyma tylko `ILocalizer`, a `App.CreateWindow` składa łańcuch obiektów ręcznie —
  `MauiDialogService`, `LoggingErrorHandler`, `NavigationService`, `new ReportService(new InMemoryReportRepository(new SystemClock()))`,
  fabryka, formatter, `UserFeedback`, ViewModel, strona

## Kryteria akceptacji
- Lista pokazuje te same 6 przykładowych zgłoszeń co wcześniej, ale dane przychodzą teraz z `ReportService`, który czyta je z `InMemoryReportRepository`.
- Obiekty usług i ViewModeli tworzy kontener DI: w kodzie nie ma `new ReportService(...)` ani `new ReportsViewModel(...)` — każda klasa dostaje zależności przez konstruktor.
- Singleton vs Transient: usługi, repozytorium i nawigacja — Singleton; ViewModele i strony — Transient.
- Z kontenera pobiera obiekty tylko korzeń kompozycji (`App`); żadna inna klasa nie sięga po usługi ręcznie
  (np. przez `BuildServiceProvider()` albo pomocnika typu `ServiceHelper.GetService<T>()`).
- `dotnet test` kończy się na zielono (w tym test z mockiem repozytorium).

## Typowe błędy (do poprawienia na żywo)
```csharp
// ❌ ręczna fabryka: każda zmiana konstruktora = zmiana tutaj
services.AddTransient(sp => new ReportsViewModel(sp.GetRequiredService<INavigationService>(), …));
// ✅
services.AddTransient<ReportsViewModel>();

// ❌ drugi kontener (osobne singletony)
var provider = builder.Services.BuildServiceProvider();

// ❌ lokalizator usług (ang. Service Locator) w ViewModelu/kontrolce — antywzorzec: zależność ukryta w kodzie
var nav = ServiceHelper.GetService<INavigationService>();
// ✅ zależność w konstruktorze
```

## Podpowiedzi
- Captive dependency: singleton, który w konstruktorze dostaje transient, trzyma go „na zawsze”.
- `InMemoryReportRepository` musi być singletonem — inaczej każda strona widziałaby inną listę.
- Mock repozytorium: `repository.Setup(r => r.GetAllAsync(It.IsAny<CancellationToken>())).ReturnsAsync([older, newer]);`
